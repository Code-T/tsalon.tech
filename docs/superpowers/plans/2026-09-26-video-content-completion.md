# 全量视频文字内容补全计划

> For agentic workers: use subagent-driven-development for independent transcript, editorial, and inventory tasks. The user has explicitly authorized completing and publishing the work; do not introduce another approval gate.

**Goal:** 先完整处理官网现有 17 期 T Chat / 34 段视频，再处理同一 B 站账号其余历史视频；完整转录与文字回顾分别交付并上线。

**Architecture:** 保留既有视频与文章 URL。离线管线下载公开音轨或真实字幕、完成转录及质量检查，原始音轨和模型留在本地。站内用轻量索引连接每期原片、自动转录 TXT/SRT 和完整叙述回顾；未完成的资源不生成链接，也不记为完成。

**Tech Stack:** Astro、Markdown、JSON、Node.js、Python、yt-dlp、faster-whisper。

**Spec:** 本对话中用户确认“包括账号全部历史视频，先完成现有 17 期”，并沿用此前直接发布生产的授权。于航现有文章不完整，需要覆盖 72 分钟技术分享与 49 分钟完整对谈。

## Global Constraints

- 不把目录、原视频链接、时间码表当成完整文字回顾。
- 每期需覆盖技术分享、访谈及实质问答；内容依据完整上下文，不凭标题生成文章。
- 自动转录明确标识，不能冒充人工逐字校听；不确定专名、数字和直接引语不猜写。
- 已有发表日期保留，新增修订日期；工作经历和技术状态使用录播当年的语境。
- 不上传音频、模型、Python 环境、凭据；不使用未经授权的付费服务。
- 网站只新增确实存在且通过校验的转录文件，未成功视频保持未完成。
- 用户要求全部历史视频，账号全量盘点独立于 17 期优先批次；必须报告剩余范围。

## Task 1: 清单与可恢复转录

- [ ] 官方账号全量视频清单：BV、标题、上传日期、分 P、时长、与现有期次关系，注明分页完整性。
- [ ] 建立 34 段优先队列，复用已完成于航两段；每项记录下载、转录、质量、编辑和发布状态。
- [ ] 优先真实字幕，无字幕则公共音轨 ASR；弹幕不可当字幕。
- [ ] 处理中断后从已完成结果恢复，不重复下载、转录或误报成功。
- [ ] 输出 TXT/SRT/JSON 与处理时长证据，逐个报告失败原因。

## Task 2: 完整回顾

- [ ] 于航：通读两段全文，制作逐主题覆盖表，扩写现有文章中的技术、经历、写作、表达、工作、学习、架构、机会及问答内容。
- [ ] 其余期次：逐期全文审阅及覆盖表，形成独立中文回顾并保留原片时间码。
- [ ] 对疑似识别错误结合连续上下文、已知原始资料纠错，不强行补入不确定内容。
- [ ] 独立复核回顾与覆盖表，确认没有整段访谈仅以提问目录替代。

## Task 3: 网站资源连接

- [ ] 在文章 schema 添加 relatedTalks；访谈页链接已公开的对应回顾，文章页链接原期次。
- [ ] 建立 transcripts.json 资源索引及完整 TXT/SRT 公共文件，提供清晰的自动转录标识。
- [ ] 共用资源组件在原访谈页和回顾页显示已完成分段，不创建未完成下载链接。
- [ ] 验证每份资源匹配原 BV、TXT/SRT 非空、音轨处理完成、所有映射指向存在的文件与期次。

## Task 4: 逐批发布与验收

- [ ] 运行内容/双语校验、相关测试、构建和内部链接检查。
- [ ] 检查生成 HTML：回顾可发现、转录全文可下载、原视频与分段正确、手机布局正常。
- [ ] 提交 PR 并在检查通过后按既有授权合并生产；核对正式域名回顾和所有下载文件。
- [ ] 更新覆盖台账，只有通过生产验收才记 published；持续处理剩余视频，不以单篇完成代替全量完成。

## Review Focus

- 一个 BV 多 P 时必须逐 P 记录，不能按 BV 数冒充视频数量。
- 识别运行结束但没有覆盖完整音轨时不能记完成。
- 没有可靠说话人分离时，不把主持人的观点写成嘉宾的直接意见。
- 不把第三方资料补入本场讲者发言；原片事实与编辑背景分清。
- 页面显示回顾与完整转录的实际完成状态，不能生成 404 资源或虚假的“全文”。
