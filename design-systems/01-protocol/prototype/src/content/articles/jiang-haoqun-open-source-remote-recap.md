这场分享讲的是一支非典型团队的工作方式。蒋豪群从 2018 年起全职参与开源；按他在片中的介绍，当时公司全职成员很少，项目协作网络却包括来自不同国家、以兼职或志愿方式参与的开发者。因此，他的经验同时涉及受雇工作和开放社区，不能直接当作所有远程公司的制度样本。

**来源说明：**本文回顾蒋豪群的开源远程工作分享，原片发布于 **2023 年 3 月 8 日**，不据此认定活动日期。下文的成员规模、工具选择、收入与合同安排均保留当时语境，段落附原片时间链接。

## 从招聘启事到长期工具链维护

蒋豪群是在社区看到招聘文章后投递简历，经过面试加入，并非先长期给 Vue 提交代码才获得工作。作为早期全职成员，他与团队一起逐步磨合流程，一直以个人贡献者的身份参与，没有承担管理岗位。

工作内容也不是招聘文案的静态清单：初期偏向具体功能实现，后来更多投入工具链维护。这类事务可能琐碎、枯燥，却需要持续投入和大量沟通。初入职时，他也并非每项工作都能立即独立完成，仍需要指导；原先设想的功能可能缩小、换一种实现，或者因更好方案出现而取消。因此，他鼓励有一定匹配度的人尝试投递，不必把招聘描述理解为入职第一天就要掌握的全部能力。[原片 02:06—05:28](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=126)

## 英语首先服务于把事情讲清楚

全球协作要求基本的英语读写能力，但团队大量沟通通过文字异步完成。他认为，表达意愿、工具使用能力，以及能否先想清楚自己要说什么，往往比一开始就写出流利英文更关键。他刚加入时，英文回复也需要憋很久；在反复处理真实问题的过程中，常用表达才逐渐熟练。

片中提到翻译、语法检查和当时的新一代 AI 写作工具，都是帮助降低语言摩擦的手段。他自己的做法是先写出要点，再根据工具提示修改语法与用词。这里记录的是其使用经验，不是对这些工具当前准确率的评测，也不能据此把技术事实判断交给生成工具。[原片 05:29—08:23](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=329)

同步会议则需要另一层准备：预先确定议程，提前写下要讲的内容，必要时准备完整发言稿。这样即使临场发挥有限，也能完成沟通；同时要能听懂对方，愿意开口。片中对 AI 生成正式英文邮件的展示，也落在同一前提上：本人先明确中心意思。[原片 08:24—09:47](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=504)

## 时间自由不等于工作自动减少

团队按任务完成情况交流，不以在线时长作为主要汇报内容。他描述自己的工作量仍接近正常全职工作；生活节奏较平衡，在他看来更多来自公司文化，而不是远程办公这个形式本身。

他经历过两个容易失控的阶段。刚开始，海外同事在自己下班后讨论技术，他忍不住看消息、开电脑，工作时间反而变长。后来，白天可以自由出门办事，但任务仍要完成，晚上补做时又容易因为身边缺少共同作息而一直工作下去。频繁打断再补偿，不一定比稳定工作更轻松，也会妨碍协作。[原片 09:48—12:56](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=588)

后来的调整是参照家人的正常作息，尽量建立可掌控的工作时段。地点也需要主动选择：他发现安静的咖啡馆或共享办公空间有时比家里更适合自己，建议寻找稳定、少干扰的工作环境。片中对在家和在外效率的比较是个人体感，不能当作所有人的量化结论；当时涉及疫情的出行顾虑也属于历史背景。[原片 12:56—15:41](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=776)

## 异步讨论要带着主题和方案

跨城市、跨时区协作，很难靠连续追问逐步拼出问题。蒋豪群强调，每次讨论最好有明确主题，并带上自己的方案。否则一句话与下一句之间可能隔几个小时，沟通链路会被放大。

团队最初围绕 GitHub issue 讨论，也使用 Slack 的话题线程；后来进一步利用 GitHub Discussions，并迁到 Discord。选择背后的考虑包括话题组织、开放参与和当时的成本：一个总问题可以展开多个子讨论，彼此不必打断；同时在线时可以直接聊天，需要深入讨论时则另开主题。具体产品和收费条件可能变化，可延续的做法是让讨论有上下文、能回看、能分支。[原片 15:42—19:04](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=942)

## 把进度同步、共同讨论和感情交流分开安排

因许多成员不是全职，片中的团队约两周开一次视频会。最初会议主要同步进度，后来发现隔两周逐人念一遍周报的投入产出有限，纯进度信息完全可以书面传递。

调整后的正式会议更多用于新特性设计、难以解决的问题和需要多人协调的事项；另设共同在线工作的时段，让大家开着摄像头各做各的事，偶尔聊天，模拟线下共处。这种 co-working session 承担的是关系与情感交流，不能替代需要形成决定的正式讨论。[原片 19:08—21:57](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1148)

跨时区排会则采用可用时间投票和日历预约工具：大团队先汇总各自当地的空闲区间，小范围沟通再预约具体时间，并在夏令时切换时调整。实际体验并非完全自由——他的会议经常落在东八区晚上，有时更晚。问答进一步说明，排期也会照顾成员的家庭安排，而不是只按职位决定谁迁就谁。[原片 21:58—24:20](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1318)、[问答 25:38—27:07](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1538)

## 生活选择与团队关系

对蒋豪群而言，远程工作让他可以住在家乡、陪伴家人。但他没有把这种生活写成唯一优解：在城市、线下活动和业余娱乐方面，他也观察到一些正常上下班的朋友拥有更丰富的选择。应比较的是自己需要的生活，而不是用远程标签直接判断自由程度。

被问到如何增进团队感情时，他认为条件允许时线下见面、参加大会仍有帮助。片中提到过去几年线下见面很少，是当时的实际经历，不能延伸成永久只在线协作的规则。[原片 24:21—25:37](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1461)、[问答 27:08—28:02](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1628)

## 问答：如何进入开源、团队靠什么运行

**从什么贡献开始？**他列出的入口不只有写代码：翻译文档、回答 issue、帮助用户解决核心成员来不及处理的问题，都能创造价值。相较偶尔出现一次的高水平贡献，持续、可靠的输出更容易让团队认识你。他举出持续投入几个月后被团队注意到的可能性，但这不是固定考核周期或录用承诺。[原片 27:38—29:27](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1658)

**必须先成为深度贡献者才能应聘吗？**他的个人路径并非如此：加入前使用 Vue 做过项目，但没有为其提交过代码。招聘进入全职岗位与通过社区贡献加入维护团队，是不同路径，不宜混为一个门槛。[原片 29:28](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1768)

**开源项目怎样获得收入？**按他当时对 Vue 的介绍，主要是社区捐赠，另有网站广告和少量合作。这个回答只说明该项目当时的构成，不能推出开源项目普遍依靠同一种商业模式。[原片 29:56](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1796)

**年龄与加入团队的流程呢？**他描述团队更关注在线技术讨论中的可靠性、能力与持续贡献，不会先了解每个人年龄。加入也没有统一的固定考察期：成员注意到持续贡献后，可以提出邀请或提名，再征求团队意见。这是该团队的实践，不代表远程行业不存在年龄门槛。[原片 30:25—32:10](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1825)

**合同、结算和税务如何处理？**最后的问答讨论了他当时采用的跨境合作安排，也提到由境内名义雇主参与的另一种模式，以及个人申报境外收入的经历。他同时指出具体法律关系因人而异。本文保留这个问题的存在及经验边界，不把片中关于合同类型、申报表格或币种的口头说明转写成今天可直接照办的操作指南；实际安排应按所在地、合同和届时规则核实。[原片 32:10—34:44](https://www.bilibili.com/video/BV1s24y1g73N?p=1&t=1930)
